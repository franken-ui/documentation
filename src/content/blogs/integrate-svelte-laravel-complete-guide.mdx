In this blog, we'll be exploring the powerful combination of Laravel, InertiaJS, and Svelte to build fast, scalable, and maintainable web applications. But before we dive in, let's take a brief look at each of these technologies and what they bring to the table.

**Laravel** - We will use Laravel 11, a popular PHP web framework that provides a robust set of tools and features for building web applications quickly and efficiently. With its elegant syntax, modular design, and extensive community support, Laravel has become a go-to choice for many developers.

**Inertia.js** - Inertia isn't a replacement for your existing frameworks, but rather a tool that works with them. It acts like a glue between server-side and client-side frameworks, using adapters to connect the two.

**Svelte** - Svelte is a lightweight JavaScript framework that compiles your code at build time, rather than at runtime. This approach allows for faster execution, smaller bundle sizes, and improved performance. Svelte's simplicity and flexibility make it an ideal choice for building complex, data-driven applications.

We'll be using the [Franken UI Laravel Template](https://github.com/franken-ui/template-laravel/) as a starting point for our project, which already comes pre-configured with Prettier for code formatting and Tailwind CSS. But don't worry if you're not a fan of Franken UI - the concepts and techniques we'll be covering can be applied to any Laravel application.

As an added bonus, we'll also be covering how to integrate SSR into our project.

## Series Overview

## Server Setup

### Install Dependencies

First, let's clone the Franken UI Laravel Template or, you can start with a fresh Laravel application.

```sh
git clone https://github.com/franken-ui/template-laravel.git
```

Then, install the Inertia server-side adapter using the Composer package manager

```sh
composer require inertiajs/inertia-laravel
```

### Root template

Next, setup the root template that will be loaded on the first page visit to your application. This will be used to load your site assets (CSS and JavaScript), and will also contain a root `<div>` in which to boot your JavaScript application.

```html
<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="utf-8" />
    <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
    <meta name="viewport" content="width=device-width" />
    <link rel="preload" href="{{ asset('fonts/geist-font/fonts/GeistVariableVF.woff2') }}" as="font"
        type="font/woff2" crossorigin />
    <link rel="preload" href="{{ asset('fonts/geist-font/fonts/GeistMonoVariableVF.woff2') }}" as="font"
        type="font/woff2" crossorigin />
    <link rel="stylesheet" href="{{ asset('fonts/geist-font/style.css') }}" />
    <script>
        if (
            localStorage.getItem("color-theme") === "dark" ||
            (!("color-theme" in localStorage) &&
                window.matchMedia("(prefers-color-scheme: dark)").matches)
        ) {
            document.documentElement.classList.add("dark");
        } else {
            document.documentElement.classList.remove("dark");
        }
    </script>

    @vite('resources/css/app.css')
    @vite('resources/js/app.js')
    @vite('resources/js/uikit.js')
    @inertiaHead
</head>

<body class="bg-background font-geist-sans text-foreground antialiased">
    @inertia

    <script>
        var themeToggleBtn = document.getElementById("theme-toggle");

        themeToggleBtn?.addEventListener("click", function() {
            // if set via local storage previously
            if (localStorage.getItem("color-theme")) {
                if (localStorage.getItem("color-theme") === "light") {
                    document.documentElement.classList.add("dark");
                    localStorage.setItem("color-theme", "dark");
                } else {
                    document.documentElement.classList.remove("dark");
                    localStorage.setItem("color-theme", "light");
                }

                // if NOT set via local storage previously
            } else {
                if (document.documentElement.classList.contains("dark")) {
                    document.documentElement.classList.remove("dark");
                    localStorage.setItem("color-theme", "light");
                } else {
                    document.documentElement.classList.add("dark");
                    localStorage.setItem("color-theme", "dark");
                }
            }
        });
    </script>
</body>

</html>
```

### Middleware

Next we need to setup the Inertia middleware. You can accomplish this by publishing the `HandleInertiaRequests` middleware to your application, which can be done using the following Artisan command.

```sh
php artisan inertia:middleware
```

Once the middleware has been published, append the HandleInertiaRequests middleware to the web middleware group in your application's `bootstrap/app.php` file.

```diff
 ->withMiddleware(function (Middleware $middleware) {
-     //
+     $middleware
+         ->appendToGroup(
+             "web",
+             \App\Http\Middleware\HandleInertiaRequests::class
+         );
 })
```

### Creating Responses

In your `routes/web.php`, you can now use the `inertia()` function instead of `view()` to render Svelte components.

```diff
 <?php

 use Illuminate\Support\Facades\Route;

 Route::get('/', function () {
-    return view('welcome');
+    return inertia('welcome');
 });
```

And that's it! You're all ready to go server-side! Now you're ready to start creating Inertia pages and rendering them via responses.

## Client Setup

Once you have your server-side framework configured, you then need to setup your client-side framework. We'll be using Svelte.

### Install Dependencies

First, let's install all the dependencies that we need.

```sh
npm i @inertiajs/svelte @sveltejs/vite-plugin-svelte svelte prettier-plugin-svelte
```

### Configuring SSR

Since we're using Laravel, a server-rendered framework, why not we take advantage of SSR too so we can get a higher score on Lighthouse, plus, our application will be a lot faster because we'll ship an already-rendered HTML upon request.

First, let's create a `resources/js/ssr.js` file.

```js
import { createInertiaApp } from "@inertiajs/svelte";
import createServer from "@inertiajs/svelte/server";

createServer((page) =>
    createInertiaApp({
        page,
        resolve: (name) => {
            const pages = import.meta.glob("./inertia/**/*.svelte", {
                eager: true,
            });
            return pages[`./inertia/${name}.svelte`];
        },
    }),
);
```

Next, let's make some changes in our `resources/js/app.js`.

```diff
+ import { createInertiaApp } from "@inertiajs/svelte";

+ createInertiaApp({
+     progress: {
+         color: "#3b82f6",
+     },
+     resolve: (name) => {
+         const pages = import.meta.glob("./inertia/**/*.svelte");
+         return pages[`./inertia/${name}.svelte`]();
+     },
+     setup({ el, App, props }) {
+         new App({ target: el, props, hydrate: true });
+     },
+ });
```

This will initialize the client-side framework with the base Inertia component. The `setup()` callback receives everything necessary to initialize the client-side framework, including the root Inertia App component. While `resolve()` callback tells Inertia how to load a page component. It receives a page name (string), and returns a page component module. 

Next, let's make some changes in our `vite.config.js` file.

```diff
 import { defineConfig } from "vite";
 import laravel from "laravel-vite-plugin";
+ import { svelte } from "@sveltejs/vite-plugin-svelte";

 export default defineConfig({
     plugins: [
         laravel({
             input: [
                 "resources/css/app.css",
                 "resources/js/app.js",
                 "resources/js/uikit.js",
             ],
+            ssr: "resources/js/ssr.js",
             refresh: true,
         }),
+        svelte({
+            compilerOptions: {
+                hydratable: true,
+            },
+        }),
     ],
+    resolve: {
+        alias: {
+            "@css": "/resources/css",
+            "@inertia": "/resources/js/inertia",
+        },
+    },
 });
```

In the example above, we configured our `vite.config.js` to include path aliases such as `@css` and `@inertia`. This setup helps to alleviate "relative path hell" by providing a more concise and readable way to import modules.

To fully leverage the benefits of these aliases, create a `jsconfig.json` file at the root of your project. It's essential to configure your code editor to recognize and follow these imports. This allows you to seamlessly navigate to the corresponding files when clicking on the imports, making your development workflow more efficient.

```json
{
    "compilerOptions": {
        "baseUrl": ".",
        "target": "es6",
        "paths": {
            "@css/*": ["./resources/css/*"],
            "@inertia/*": ["./resources/js/inertia/*"],
        }
    }
}
```

Next, update our `tailwind.config.js` file and add `.svelte` extensions to the list so it can also watch Svelte files for changes.

```diff
 content: [
+    "./resources/**/*.blade.php",
+    "./resources/**/*.js",
+    "./resources/**/*.svelte",
 ],
```

Finally, update our package.json to allow our SSR to be built as well when we run npm run build.

```diff
 "scripts": {
    "dev": "vite",
-   "build": "vite build"
+   "build": "vite build && vite build --ssr"
  },
```

And there we have it! We have set up Svelte with Laravel and configured it with SSR. Stay tuned for my next post, where I will teach how to deploy it to a live server and make it accessible to the public.
